# v0.2 preview validation

## Recorded fresh-project path

`composer test:project` creates a disposable scaffold, resolves production dependencies with Composer and boots the real Tempest discovery/composition flow. It uses a PSR-18 recorder and an in-process Socket Mode connection; no Slack credentials or Slack network calls are needed. Child processes inherit an allowlist of runtime/executable paths and fixed fixture variables rather than ambient application tokens.

The fixture exercises:

1. Generated app/listener/job scaffolding, discovered handlers and explicit static identity verification.
2. A fresh OAuth configuration and HTTP installation flow carrying server-side account metadata; credentials and account association persist before the next delivery. Callback replay does not exchange another code.
3. A signed mention, two signed button deliveries, and the same button over Socket Mode.
4. Both configured transport factories load the account association from disk after installation authorization. Typed action/form readers produce the same explicit job data on both transports.
5. All three button deliveries deduplicate into one SQLite job. The fixture claims its lease and expires only that disposable lease to simulate process death.
6. A new `jobs:work --once` process recovers the lease, records attempt two, and writes the expected receipt. Its live Context has no request account or transport values, and its scoped Web API client uses the stored installation credential.
7. Operator history records `lease_expired_retry`; another worker invocation has no work. The temporary project is removed without following the package's source symlink.

Fixture files stay `.php.stub` to prevent Tempest from discovering/executing standalone validation scripts during the library's test discovery. Both Linux and macOS CI already run `composer test:project`; this expands that existing gate.

## Live scope

The existing opt-in live read check passed on 28 October 2026: five conversation read methods and bounded pagination, 9 assertions. `SLACK_LIVE_WRITES=0` kept the metadata write round trip skipped; no Slack message was sent or changed in this release run. The new installation/interaction/context paths are validated with recorded protocol fixtures, not a newly completed browser installation or manual live form submission. Paid-plan custom-function validation remains unavailable in the development workspace.
