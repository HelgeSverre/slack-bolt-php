# PHP design decisions

## One deep listener boundary — 🟡

The normal handler boundary is a typed, readonly Slack payload plus `Reply`. An optional `Thunder\Bolt\Invocation\Delivery` parameter exposes delivery-scoped metadata, selector matches, and the resolved listener when that advanced context is needed. Attributes belong on public handler methods; attributes and fluent registration compile to one canonical descriptor and duplicate descriptors report both sources. This prevents the common split between attributes, context bags, and registration APIs.

```php
final class MentionHandler
{
    #[Event('app_mention')]
    public function __invoke(AppMention $event, Reply $reply): void
    {
        $reply->inThread(
            Message::blocks(Section::markdown('Hello'))
                ->fallbackText('Hello'),
        );
    }
}
```

`Reply::inThread()` resolves the incoming root to `thread_ts ?? ts` and deliberately overrides a destination carried by a reusable message. `Message::inThread($rootTs)` is for an explicit destination in a direct Web API call. The receiver handles the initial HTTP acknowledgement; normal handlers receive neither a response object nor a generic acknowledgement capability.

## Acknowledgement invariant — 🟢

Slash-command listeners must produce exactly one returned `CommandResponse` across all matching listeners. Event acknowledgements are generated by the receiver. Execution is inline: the response is emitted after dispatch completes and must still meet Slack's three-second deadline. `Reply` and `Client` make outbound Web API calls; neither flushes an early HTTP acknowledgement. Optional workers remain future adapters.

## Modern PHP strengths — 🟡

Immutable message and Block Kit builders provide named factories and method chaining; readonly request values preserve parsed Slack input; PHP attributes make discoverable handlers concise; generators fit cursor pagination; PSR clients make transport replaceable. Typed payloads cover stable, known envelope shapes, while unknown events retain raw data through a generic payload so the framework never invents a shape.

## Explicit deviations — 🟢

`App` defaults to in-process HTTP handling, as requested. Worker and Socket Mode execution are optional adapters. Generated endpoint groups are minimal honest forwarders; rich request DTOs are handwritten only where their validation is valuable. There is no automatic Web API retry in the first slice: callers receive `RateLimited` with `retryAfter`. This is easier to reason about in PHP request lifecycles than an invisible sleep/retry loop.
