## Verification and limits

- Release dependency audit found the newly published [Symfony Filesystem advisory](https://github.com/symfony/symfony/security/advisories/GHSA-6prc-h956-hxjq) and [YAML advisory](https://github.com/symfony/symfony/security/advisories/GHSA-hwfg-qwvh-2wfx) in the previous lockfiles. Both packages were updated to patched v8.1.11 in the framework and demo lockfiles; unrelated transitive versions were retained.
- After the dependency update, the full suite and fresh path/VCS projects passed again. All three demo processes booted with the patched dependencies; Home refresh completed and a separate durable AI job produced the visible [“Release smoke passed.” response](https://helgesverre.slack.com/archives/D0CBLL7LF51/p1793869680112689). `composer audit` reported no advisories.
- Full runtime suite: **1,225 tests, 6,785 assertions**, passing. The new regressions verify successive fresh grants and terminal owner isolation through signed delivery.
- Mago analysis has no errors; nonfatal advisories remain visible. Formatting and lint use the existing configured gates.
- The lost-response case is controlled transport fault injection after a real Slack acceptance, not a claim to have reproduced a spontaneous Slack network outage. The receiver error case is explicitly a signed loopback probe.
- No new permissions were requested. OAuth rotation is the approved persistent app-setting change. OAuth consent, new scope grants and app-level token rotation were not performed.
- The UI acceptance's synthetic Work Object mention verifies its inline reference; the separate native task above verifies the demo's hydrated object path. Neither establishes all external object access policies or all Slack clients.
