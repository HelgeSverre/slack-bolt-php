# Bug hunt and small-feature inventory — 4 November 2026

**5 November follow-up:** [v0.8.0 verification](v0.8-release-verification.md) records the subsequent live checks, fixes discovered during migration and release status. The findings and unreleased status below describe the original review checkpoint.

Review baseline: `ddee2412d65b6701519e1d839dc2280af5acec74`, following v0.7.0. Five agents independently reviewed bugs in runtime/delivery, OAuth, durable execution/context storage, SDK/Block Kit and CLI/scaffolding. Three more independently reviewed everyday PHP ergonomics, developer tooling and Slack capability gaps. The parent checked findings against intended contracts and coordinated bounded fixes.

This is a scoped source-and-reproduction review, not proof that every code path or Slack workspace feature is correct. The review used synthetic local inputs and disposable applications; it did not read credentials or change live Slack settings. Fixes in this round are unreleased and remain subject to the [live release gate](../development.md#live-release-verification).

## Confirmed findings and corrections

All findings below are medium-priority correctness/foot-gun issues. None was established as a critical exploit.

| ID | Failure at the review baseline | Correction and regression seam |
| --- | --- | --- |
| BH-01 | Rotating bot and user credentials returned the user snapshot with a stale bot token, despite a successful fresh bot record. | [`TokenRotator`](../../src/OAuth/TokenRotator.php) combines current selected grants; bot-only/missing-user results omit an embedded installer's user grant. [`TokenRotatorTest`](../../tests/OAuth/TokenRotatorTest.php) checks fresh access/refresh tokens, independent refresh metadata and missing-user selection. |
| BH-02 | A valid options acknowledgement containing invalid UTF-8 threw during JSON serialization outside the HTTP receiver's failure boundary. | [`Receiver`](../../src/Http/Receiver.php) serializes once inside its guarded path. [`ReceiverFailurePolicyTest`](../../tests/Http/ReceiverFailurePolicyTest.php) verifies controlled 500 and custom receiver-error policy. Socket Mode already guards serialization/send failures. |
| BH-03 | Containers accepted no children, collapsed-but-not-collapsible state and collapsibility combined with a header divider. | [`Container`](../../src/BlockKit/Container.php) requires 1–10 children and validates final flag combinations. [`ModernBlocksTest`](../../tests/BlockKit/ModernBlocksTest.php) covers failures and valid modifier ordering. |
| BH-04 | Alerts accepted 201–3,000 characters, beyond Slack's 200-character limit. | [`Alert`](../../src/BlockKit/Alert.php) checks its narrower limit, with boundary coverage in [`SpecialistBlocksTest`](../../tests/BlockKit/SpecialistBlocksTest.php). |
| BH-05 | Cards accepted four or more action buttons, beyond Slack's limit of three. | [`Card`](../../src/BlockKit/Card.php) rejects the fourth action, with regression coverage in [`SpecialistBlocksTest`](../../tests/BlockKit/SpecialistBlocksTest.php). |
| BH-06 | Generators treated a dangling symlink file as absent and wrote through it to an unintended target. | [`ProjectScaffold`](../../src/Console/ProjectScaffold.php) refuses existing links for listener, job/handler and assistant targets. [`ProjectScaffoldTest`](../../tests/Console/ProjectScaffoldTest.php) proves targets are preserved and partial files are not emitted. |
| BH-07 | Running a project command before installing dependencies emitted a Tempest stack trace rather than a useful setup diagnostic. | [`BoltCli`](../../src/Console/BoltCli.php) detects missing Composer installation metadata and exits 1 with an install instruction. [`OnboardingBootstrapTest`](../../tests/Console/OnboardingBootstrapTest.php) preserves doctor/status JSON behavior. |
| BH-08 | After a Slack stream write with a lost response, the AI demo could post a fallback answer even if Slack accepted the original write. The durable job could then appear successful despite duplicate output. | [`SlackAnswerStream`](../../examples/hello-bolt/app/Demo/Ai/SlackAnswerStream.php) propagates ambiguous writes as `Jobs\UncertainOutcome` instead of replaying or posting a second answer. Block limits were checked against Slack's [container SDK contract](https://docs.slack.dev/tools/node-slack-sdk/reference/types/interfaces/ContainerBlock/), [alert reference](https://docs.slack.dev/reference/block-kit/blocks/alert-block/) and [card reference](https://docs.slack.dev/reference/block-kit/blocks/card-block/). Unit serialization alone does not prove rendering; these validation fixes do not replace live acceptance before release.

## Findings not promoted to fixes

- A writer already controlling the private installation-store directory can tamper with its records. A lock-file symlink demonstration did not establish a separate supported-boundary exploit; broader filesystem hardening was excluded from the confirmed bug list.
- Direct installation-store bot snapshots can contain fields from the installing user's OAuth response. `InstallationAuthorizer` performs explicit per-delivery grant selection. This is a low-level API design foot-gun, not a confirmed authorization bypass. The guide now distinguishes persisted snapshots from authorization results. Broader projection semantics need a separate compatibility decision.
- Following symlinked project parent directories is normal developer filesystem behavior; only generator file-target overwrite guards changed. Completion catalog regeneration can intentionally overwrite its generated output; it was not treated as a confirmed destructive-generator defect.
- Some manual plain-text builders omit Slack's optional `emoji` field. The earlier nested-stream issue does not prove all such shapes fail. No broad change was made without a targeted live reproduction.

## Ranked small additions

These are proposals, not implemented APIs. Existing raw payloads remain supported.

| Rank | Addition | Existing friction / bounded approach |
| --- | --- | --- |
| 1 | Typed view operations | Generated view requests accept `mixed` views and examples mostly hand-build arrays. Native builders already work through generated request values and JSON serialization; the gap is stronger view/surface validation and simpler discovery. Add small handwritten request values accepting compatible native views, explicit destinations/triggers and optimistic hashes; keep generated DTOs unchanged. Both API ergonomics reviewers independently recommended this. |
| 2 | Message update and ephemeral request values | Posting has [`ChatPostMessage`](../../src/WebApi/Requests/ChatPostMessage.php), while update/ephemeral callers merge `Message::toArray()` manually. Add sibling request values with explicit channel, user and timestamp; response-URL visibility conveniences can remain thin `Reply` methods. |
| 3 | Better public test fixtures and assertions | [`BoltTest`](../../src/Testing/BoltTest.php) requires raw interaction envelopes and [`TestResult`](../../src/Testing/TestResult.php) needs predicate closures for nested API arguments. Add typed interaction fixture factories and recursive-subset API assertions. This improves tests without simulating Slack's entire protocol. |
| 4 | Modern rich-text references | Tags and message/Work Object mentions currently need `RichText::fromElements()` raw arrays. Small immutable leaf values fit existing rich-text builders; Work Object cases still need an eligible live workspace. |
| 5 | Opt-in test-ready `bolt new` | Offer a PHPUnit option adding a test directory/config, dev dependency, script and one `BoltTest` starter. Keep the default generated application test-runner neutral. |

Secondary opportunities: typed stream options, channel-level suggested-prompt requests for Agent View, ordinary link-unfurl builders and typed scheduling requests. Native citation details are useful but wider than a quick leaf builder. Avoid expanding into Laravel integration, Node host emulation or exhaustive TypeScript union replication.

Each addition needs focused tests and updated examples; Slack-facing additions also need the corresponding live interaction/rendering check before release. Unfurls require a registered domain and link scopes; richer Work Object/citation features may have workspace availability constraints.

## Combined verification

After the independent fixes were assembled, the parent ran:

- Full suite: **1,197 tests, 6,650 assertions**, passing.
- Fresh production applications: path-source and disposable Git-source smoke checks, both passing. These include installed discovery, typed HTTP/Socket interactions, OAuth metadata, durable recovery and Agent View/Stop fixtures.
- Mago format, lint and analysis: configured error checks passing. Existing nonfatal lint/analysis advisories remain; this is not a claim of an advisory-free codebase.
- Documentation verification: **85 owned Markdown files, 926 local links and 81 PHP snippets**, passing; `git diff --check` clean.

No live Slack acceptance was performed for these fixes, and no release was published in this round. The simulated ambiguous-write tests verify that uncertain writes do not cause a second request; they do not claim to reproduce Slack's internal server state after an actual lost network response.
